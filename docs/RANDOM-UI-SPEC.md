# 랜덤 뽑기 / 관리자 페이지 — UI 재설계용 기능 명세

> 대상: `public/random.html`(랜덤 뽑기), `public/random-admin.html`(관리자 페이지)
> 목적: 두 페이지를 코드가 아니라 **화면·행동·상태** 단위로 재정리해서 UI 재설계 착수 자료로 쓴다.
> 스크린샷은 프로덕션(`oc-yeonsung.lunayeon.com`)에서 실제 데이터로 찍었다. 데스크톱 폭(약 880px 컨테이너) 기준이며, 두 페이지 모두 480px 이하에서 별도 모바일 축소 스타일(글자 크기·여백만 축소, 레이아웃 구조는 동일)이 적용된다.

```

│                    랜덤 뽑기                    │ ← 페이지 헤더 (h1)

│ │  인원 [1][2][3][4][5]                       │ │

│ │  ─ 결과 표시 ───────────────                │ │
│ │  이름1 ✕ 이름2      (플레이스홀더: ??? ✕ ???) │ │

│ │  관계성: 값 [🔄 리롤]                         │ │
```

### ② 사용자가 할 수 있는 모든 행동 (트리거 → 결과)

**뽑기 존**
| 트리거 | 결과 |
|---|---|
| 인원 수 버튼(1~5) 클릭 | 참가자 수 변경 → 결과가 플레이스홀더(`???`)로 초기화, 위치 탭 개수가 그만큼 재생성, 잘라낸 인원의 개별 오버라이드는 폐기 |
| **뽑기!** 클릭 (후보 있을 때만 활성) | 이름/설정/관계성 칸이 0.05~0.14초 간격으로 16~25회 빠르게 바뀌다가(슬롯머신 효과) 최종값에 멈춤 → 버튼 주변에 색종이 파티클 12개 발사 → 결과 액션 버튼 노출 → 히스토리 맨 앞에 1줄 추가(최대 20개, 넘으면 오래된 것부터 삭제) |
| **🔄 리롤**(설정) 클릭 (결과 있을 때만) | 캐릭터 설정 값만 재추첨(이름·관계성은 유지), 짧은 슬롯 애니메이션 후 확정 |
| **🔄 리롤**(관계성) 클릭 | 관계성 값만 재추첨 |
| **📋 결과 복사** 클릭 | 현재 결과를 `이름1(설정1) ✕ 이름2(설정2) / 관계성` 형식 텍스트로 클립보드 복사, 토스트 "복사되었습니다" |
| **💾 저장소에 저장** 클릭 | "저장소에 저장" 선택 모달(유저 3명 중 선택) 열림 → 유저 선택 시 해당 유저의 뽑기 보관함에 저장, 토스트 "OO님의 뽑기 보관함에 저장했어요" |
| 히스토리 칩 클릭 | 그 결과 텍스트를 클립보드로 재복사 |
| **초기화**(히스토리 옆) 클릭 | 히스토리 전체 비움 |

**목록 조회**
| 트리거 | 결과 |
|---|---|
| **⚔️ 캐릭터 설정 전체 확인** 클릭 | 모달에 역할 태그 전체를 그룹별로 정렬해 나열(가나다순) |
| **🌀 관계성 전체 확인** 클릭 | 모달에 관계성(AU) 태그 전체를 그룹별로 나열 |
| 모달 [✕] / [닫기] / 모달 바깥 클릭 | 모달 닫힘 |

**후보 풀**
| 트리거 | 결과 |
|---|---|
| 풀 탭(`🎯 공통 후보` / `위치N`) 클릭 | 아래 후보 그리드가 해당 탭의 선택 상태로 전환. `위치N` 탭인데 그 위치가 오버라이드 안 돼 있으면 공통 후보를 **읽기 전용**으로 그대로 보여줌 |
| **이 위치만 다르게 설정** 체크 (위치 탭에서만 노출) | 해당 위치가 공통 후보에서 분리되어 독립 편집 가능해짐(초기값 = 현재 공통 후보 복사본). 탭 라벨에 `•` 표시가 붙음 |
| 체크 해제 | 그 위치의 커스텀 선택을 버리고 다시 공통 후보를 따라가는 읽기 전용 상태로 복귀 |
| (오버라이드 중) 소스 드롭다운 선택 + **이대로 가져오기** 클릭 | 다른 탭(공통 후보 또는 다른 위치)의 선택 목록을 통째로 복사해 옴, 토스트 "선택을 복사했어요" |
| 캐릭터 칩 클릭 (편집 가능한 탭에서만) | 그 캐릭터를 현재 탭의 후보 목록에 추가/제거(토글). 체크마크·보라 강조로 표시 |
| 오너 이름 옆 **전체 선택** 클릭 | 그 오너 소속 캐릭터를 (필터가 걸려 있으면 필터 통과분만) 전량 켜기/전량 끄기 토글 |
| 풀 카드 헤더 **전체 선택** 클릭 | 현재 탭의 전체 캐릭터를 전량 켜기/전량 끄기 토글 |
| 필터 버튼(남성만/여성만/솔로만/커플만) 클릭 | 현재 탭 기준으로 조건에 안 맞는 캐릭터 칩이 흐리게(선택 불가하진 않음, 그냥 회색 처리) 바뀜. 남성만↔여성만, 솔로만↔커플만은 서로 배타적(하나 켜면 반대쪽 자동 꺼짐). 필터는 **탭마다 별도로 기억**됨 |

**드래그**: 이 페이지에는 드래그 조작이 전혀 없다(순서 변경 기능 자체가 없음).
**키보드**: 텍스트 입력 필드가 없어 페이지 자체의 키보드 단축키도 없다.

### ③ 상태 목록

| 상태 | 트리거 | 보이는 것 |
|---|---|---|
| **로딩** | 페이지 최초 진입 | 스피너 + "데이터 불러오는 중..." 문구만 표시, 본문 전체 숨김 |
| **오프라인(폴백)** | 최초 로드 API 실패 | 내장된 기본 캐릭터/설정/관계성 데이터로 화면을 채우고 토스트 "오프라인 모드 (로컬 데이터)", 상단 sync-badge가 빨간 점 + "오프라인"으로 전환 |
| **초기(후보 없음)** | 로드 직후, 아무것도 선택 안 함 | 공통 0개, 결과는 `???` 플레이스홀더, **뽑기!** 버튼 비활성(회색) |
| **후보 선택됨** | 캐릭터 칩 1개 이상 켬 | **뽑기!** 버튼 활성화. 단, 인원수만큼의 **모든 위치**(공통 또는 오버라이드)에 후보가 1명 이상 있어야 활성화됨 |
| **뽑는 중(스피닝)** | 뽑기! 클릭 직후 ~1.5초 | 이름/설정/관계성 칸이 빠르게 랜덤 값으로 깜빡임, 뽑기 버튼과 리롤 버튼 모두 비활성 |
| **결과 있음** | 스핀 종료 | 최종 이름/설정/관계성 확정 표시(포착 애니메이션), 결과 액션(복사/저장) 버튼 노출, 리롤 버튼 재활성화 |
| **필터 활성** | 필터 버튼 1개 이상 켬 | 조건 안 맞는 캐릭터 칩이 투명도 낮아지고 클릭 불가 상태로 바뀜(선택은 유지되지만 더 못 켬/끔) |
| **위치 탭 · 읽기 전용** | 오버라이드 안 한 위치 탭 선택 | 안내문 "이 위치는 공통 후보를 그대로 사용 중이에요…" 노출, 칩은 보이지만 클릭 반응 없음(연한 스타일) |
| **위치 탭 · 커스텀 편집 중** | 그 위치의 오버라이드 체크 켬 | 칩 클릭 가능, 상단에 "다른 탭에서 가져오기" 컨트롤 노출, 탭 라벨에 `•` |
| **모달 열림** | 목록 확인 버튼 클릭 | 배경 어둡게 딤 처리 + 블러, 모달만 인터랙션 가능 |
| **후보 부족(중복 발생)** | 인원수보다 겹치지 않는 후보가 부족한 상태로 뽑기 | 결과는 나오되 토스트 "후보가 부족해서 일부 캐릭터가 중복됐어요" |

### ④ API / 데이터

| 시점 | 호출 | 읽는/쓰는 데이터 |
|---|---|---|
| 최초 로드 | `GET /api/characters`, `GET /api/roles`, `GET /api/aus`, `GET /api/users` (병렬) | 캐릭터 트리(오너→그룹→캐릭터), 역할 태그 트리, 관계성 태그 트리, 유저 3명 목록 — **전부 읽기 전용**, 이 페이지에서 수정 불가 |
| 로드 후 7초마다 반복 | 위 중 캐릭터/역할/관계성 3개를 각각 독립 폴링 | 관리자 페이지 등에서 바뀐 내용을 실시간에 가깝게 반영. 실패 시 상단 배지만 "오프라인"으로 바뀌고 화면은 유지 |
| **💾 저장소에 저장** 클릭 시 | `POST /api/users/{user}/draw-box` | `{ names, roles, au, memo:'' }` — 방금 뽑은 결과를 그 유저의 "뽑기 보관함"에 새 항목으로 기록(쓰기는 이게 유일함) |

이 페이지는 **캐릭터 로스터도, 역할/관계성 어휘도 만들거나 고치지 않는다** — 전부 `random-admin.html`에서 만들어진 데이터를 읽기만 하고, 그 결과를 뽑아서 유저 보관함에 저장하는 것까지가 이 페이지의 쓰기 범위다.

## 2. `random-admin.html` — 관리자 페이지

### ① 화면 영역 구분

```
┌─────────────────────────────────────────────┐
│ [← 홈]                          [🎲 랜덤 뽑기] │ ← 최상단 고정
│                  관리자 페이지                  │ ← 페이지 헤더
│ [🎭 캐릭터] [⚔️ 캐릭터 설정] [🌀 관계성]         │ ← 탭 바 (3개 패널, 한 번에 1개만 보임)
│                                                 │
│  ── "🎭 캐릭터" 탭일 때 ──                       │
│  ┌ 그룹 추가 카드 ───────────────────────────┐  │
│  │ [오너▾] [그룹이름 입력]        [그룹 추가]  │  │
│  ├ 캐릭터 추가 카드 ─────────────────────────┤  │
│  │[오너▾][그룹▾][이름 입력][성별▾][커플▾][추가]│  │
│  ├ ID 일괄 부여 카드 ────────────────────────┤  │
│  │ 설명 문구                [⚡ ID 일괄 부여 실행]│  │
│  └───────────────────────────────────────┘  │
│  캐릭터 목록 (오너별 카드, 카드 안에 그룹별 섹션)   │
│    김굥 [k]                                    │
│      ▲▼ 02즈(01) 4명            [그룹 삭제]     │
│        ▲▼ 도아랑  k0101 ♀ 솔로  [변경][✕]       │
│        ▲▼ 백설호  k0102 ♂ 솔로  [변경][✕]       │
│        ...                                     │
│                                                 │
│  ── "⚔️ 캐릭터 설정" 탭일 때 (§3 참고) ──         │
│  ── "🌀 관계성" 탭일 때 (§3 참고) ──              │
└─────────────────────────────────────────────┘

모달 A — 캐릭터 수정 (item-edit "변경" 클릭 시):
┌───────────────────────┐
│ [✕]  🎀               │
│  캐릭터 수정            │
│  이름  [___________]   │
│  오너  [드롭다운▾]      │
│  그룹  [드롭다운▾]      │
│  성별  [드롭다운▾]      │
│  커플여부[드롭다운▾]    │

│         [취소] [저장]   │
└───────────────────────┘

모달 B — 이름 변경 (role/au/태그 공용):
┌───────────────────────┐
│ [✕]  🎀               │
│  {유형별 제목}           │
│  이름 [___________]     │
│  태그 [드롭다운▾]  ← role/au 항목일 때만 노출, 태그 자체 이름변경일 땐 숨김 │
│         [취소] [저장]   │
└───────────────────────┘

전체화면 오버레이 — "저장 중..." (모든 쓰기 동작 시 짧게 표시)

```

### ② 사용자가 할 수 있는 모든 행동 (트리거 → 결과) — "캐릭터" 탭

| 트리거 | 결과 |
|---|---|
| 상단 탭(🎭/⚔️/🌀) 클릭 | 해당 패널만 보이도록 전환(단순 표시 전환, 데이터 재요청 없음) |
| **그룹 추가**: 오너 선택 + 그룹명 입력 + [그룹 추가] | 즉시 저장(API 호출) → 목록에 새 그룹 반영, 코드가 오너 내 그룹 번호로 자동 채번 |
| **캐릭터 추가**: 오너/그룹/이름/성별/커플여부 선택 + [추가] | 즉시 저장 → 목록에 새 행 반영, `publicCode`가 `오너코드+그룹코드+순번`으로 자동 부여(오너·그룹에 코드가 있을 때만) |
| **[⚡ ID 일괄 부여 실행]** | 코드 없는 오너가 하나라도 있으면 토스트로 막고 중단. 아니면 "ID 없는 캐릭터 N명에게 부여합니다, 계속할까요?" 확인 모달 → 확인 시 일괄 저장 |
| 캐릭터 행의 **▲ / ▼** | 같은 그룹 내에서 캐릭터 순서를 한 칸 위/아래로 즉시 교체 저장(맨 위/맨 아래에서는 비활성) |
| 그룹 헤더의 **▲ / ▼** | 같은 오너 내에서 그룹 순서를 한 칸씩 즉시 교체 저장 |
| 캐릭터 행 **변경** 클릭 | "캐릭터 수정" 모달 열림(현재 값으로 미리 채워짐) |
| 모달에서 이름/오너/그룹/성별/커플여부/메모 수정 후 **저장** | 유효성 확인(이름 필수, 같은 그룹에 동명이인 불가) 후 저장. **오너·그룹을 바꾸면 그 캐릭터가 원래 위치에서 빠져 새 위치로 옮겨감**(대표 이미지·커스텀 섹션 등 다른 정보는 그대로 유지) |
| 모달 **취소** / [✕] / 바깥 클릭 | 아무것도 저장하지 않고 닫힘 |
| 캐릭터 행 **✕**(삭제) | "OO 삭제할까요?" 확인 → 확인 시 즉시 삭제·저장 |
| 그룹 헤더 **그룹 삭제** | "OO 그룹 전체를 삭제할까요?" 확인 → 확인 시 그룹과 소속 캐릭터 전부 삭제 |

> 오너 추가 카드, 오너 삭제 버튼은 코드상 존재하지만 화면에서 숨겨져 있다(오너는 김굥/하지/예밍 3명 고정 운영 방침 — 실수 방지 목적). 재설계 시 "오너 관리"는 아예 화면에 없는 기능으로 취급해도 된다.

**드래그**: 순서 변경은 전부 ▲▼ 버튼이며, 이 페이지에도 드래그 앤 드롭은 없다.
**키보드**: 이 탭에는 Enter로 제출되는 입력 필드가 없다(추가 버튼을 직접 눌러야 함).

### ③ 상태 목록 — "캐릭터" 탭

| 상태 | 트리거 | 보이는 것 |
|---|---|---|
| **로딩** | 최초 진입 | 스피너 + "데이터 불러오는 중..." (본문은 `display:block`으로 이미 숨겨져 있지 않아, 실제로는 로딩 문구와 빈 목록이 잠깐 같이 보일 수 있음 — 아래 참고) |
| **연결 실패** | 최초 API 실패 | 로딩 영역 문구가 빨간 글씨 "연결 실패. 새로고침 해주세요."로 바뀌고 그대로 멈춤(폴백 데이터 없음 — `random.html`과 다름) |
| **기본 상태** | 정상 로드 | 추가 폼 3장 + 오너별 캐릭터 목록 카드 |
| **모달 열림(수정)** | 캐릭터 "변경" 클릭 | 배경 딤 처리, 캐릭터 수정 폼 |
| **저장 중** | 추가/수정/삭제/순서변경/ID일괄부여 등 쓰기 동작 직후 | 전체 화면에 반투명 오버레이 + "저장 중..." 스피너(짧게, 저장 API 응답 올 때까지) |
| **빈 목록** | 오너 자체가 0명(운영상 거의 없음) | "캐릭터가 없습니다" 문구만 |
| **그룹/오너 안 비어있지만 캐릭터 0명** | 그룹은 있는데 캐릭터가 없음 | 그룹 섹션은 그대로, 안에 "비어있음" 문구 |

> ⚠️ 코드 확인 결과: `#mainContent`가 처음부터 `style="display:block"`으로 박혀 있어 `#loadingState`(`display:none`)와 실제로는 동시에 존재한다 — 로딩 상태가 사실상 화면에 노출되지 않고, 로드가 끝나기 전까지는 **빈 탭/빈 목록이 그대로 보이는 상태**가 실질적인 "로딩 중" 화면이다. 재설계 시 이 부분은 실제로 로딩 스피너가 보이도록 고치는 편이 나을 수 있다.

### ④ API / 데이터 — "캐릭터" 탭

| 시점 | 호출 | 데이터 |
|---|---|---|
| 최초 로드 + 7초마다 폴링 | `GET /api/characters` | 오너→서브그룹→캐릭터 전체 트리 |
| 그룹 추가/캐릭터 추가/순서 변경/오너·그룹 이동/삭제/ID 일괄 부여 — **전부 공통** | `PUT /api/characters` | 클라이언트가 들고 있는 트리 전체를 그대로 보내 서버가 통째로 upsert(부분 patch가 아니라 **트리 전체 재전송**) |
| 캐릭터 단건 수정(이름/오너/그룹/성별/커플/메모, "캐릭터 수정" 모달) | 위와 동일하게 `PUT /api/characters`(트리 전체 재전송) — 별도의 단건 patch API(`PUT /api/characters/:id`)가 서버엔 있지만 **이 화면은 안 씀** | 위와 동일 |

즉 이 탭의 모든 쓰기 동작은 결과적으로 **캐릭터 트리 전체를 한 번에 다시 저장**하는 단 하나의 엔드포인트로 수렴한다 — 화면에는 "그룹만 옮겼다"처럼 작은 동작으로 보여도, 실제로는 매번 트리 전체가 왕복한다.

## 3. 역할 / 관계성 어휘 편집 (별도 섹션)

`random-admin.html`의 나머지 두 탭 — **⚔️ 캐릭터 설정**(=역할, `oc_roles`)과 **🌀 관계성**(=AU, `oc_aus`) — 은 서로 완전히 같은 구조를 공유한다(태그 그룹 안에 자유 텍스트 항목 목록). 아래는 두 탭에 공통으로 적용된다.

### ① 화면 영역 구분

```
┌ 태그 추가 카드 ───────────────────────────┐
│ [태그 이름 입력]                 [태그 추가] │
├ 항목 추가 카드 ───────────────────────────┤
│ [태그▾] [이름 입력]                  [추가] │
├ 목록 카드 ────────────────────────────────┤
│  {패널 제목} 목록                     85개  │  ← 전체 항목 개수
│  {태그 라벨 A}  40개      [태그 변경][태그 삭제]│
│    1  항목               [변경][✕]         │
│    2  항목               [변경][✕]         │
│  {태그 라벨 B}  ...                        │
└───────────────────────────────────────┘
```
스크린샷: 캐릭터 설정 탭 `screenshots/admin-04-roles-tab.jpg`, 관계성 탭 `screenshots/admin-05-aus-tab.jpg`, 이름변경 모달 `screenshots/admin-06-rename-modal.jpg`.

### ② 트리거 → 결과

| 트리거 | 결과 |
|---|---|
| 태그 이름 입력 + **태그 추가** | 새 그룹(태그) 생성, 즉시 저장. 같은 이름 있으면 토스트로 거부 |
| 태그 선택 + 항목 이름 입력(**Enter** 또는 **추가** 버튼) | 그 태그 그룹 아래 새 항목 추가, 즉시 저장. 태그가 하나도 없으면 "태그를 먼저 추가해주세요" |
| 항목 **변경** 클릭 | "수정" 모달 열림 — 이름 입력 + **소속 태그를 바꿀 수 있는 드롭다운** 동시 노출 |
| 모달에서 이름/태그 수정 후 **저장** | 원래 태그 그룹에서 항목을 빼서 선택한 태그 그룹으로 옮기고 저장(**항목이 다른 태그로 이동 가능**) |
| 항목 **✕**(삭제) | "OO 삭제할까요?" 확인 후 삭제 |
| 태그 헤더 **태그 변경** 클릭 | "수정" 모달이 열리되 이번엔 **태그 드롭다운 없이 이름 입력만** 노출(태그 자신의 라벨만 바꿈) |
| 태그 헤더 **태그 삭제** | "OO 태그와 하위 항목을 모두 삭제할까요?" 확인 → 태그와 그 안의 항목 전부 삭제 |

이름 변경 모달은 role/au/roleTag/auTag 4가지 대상을 **제목과 태그-드롭다운 노출 여부만 바꿔가며** 하나의 마크업으로 재사용한다 — 재설계 시 이 하나의 컴포넌트로 4가지 케이스를 다 커버해야 함을 염두에 둘 것.

### ③ 상태 목록

| 상태 | 트리거 | 보이는 것 |
|---|---|---|
| **태그 없음** | 해당 어휘(역할 또는 AU)에 태그가 하나도 없음 | "태그가 없습니다. 태그를 먼저 추가해주세요." (항목 추가용 태그 드롭다운도 비어서 추가 자체가 막힘) |
| **태그는 있는데 항목 없음** | 그룹은 있고 항목 0개 | 그룹 헤더 "0개" + 안에 "비어있음" |
| **정상 목록** | 데이터 있음 | 그룹별 카운트 + 번호 매겨진 항목 목록 |
| **모달 열림(항목 수정)** | 항목 "변경" | 이름 입력 + 태그 이동 드롭다운 |
| **모달 열림(태그 이름만 수정)** | 태그 헤더 "태그 변경" | 이름 입력만, 태그 드롭다운 숨김 |
| **저장 중** | 모든 쓰기 동작 | 전체화면 "저장 중..." 오버레이 |

### ④ API / 데이터

| 시점 | 호출 |
|---|---|
| 최초 로드 + 7초 폴링 | `GET /api/roles`, `GET /api/aus` (각각 `{groups:[{label, items:[...]}]}` 형태) |
| 태그 추가/삭제, 항목 추가/삭제/이동, 태그 이름 변경 — 캐릭터 설정 쪽 전부 | `PUT /api/roles` (트리 전체 재전송) |
| 위와 동일하되 관계성 쪽 | `PUT /api/aus` (트리 전체 재전송) |

캐릭터 탭과 마찬가지로, "항목 하나 이름 바꾸기"처럼 보이는 동작도 실제로는 **그 어휘(역할 또는 관계성) 전체를 통째로 다시 저장**한다.

## 부록 — 두 페이지가 공유하는 것 / 안 하는 것

- **디자인 토큰**: `assets/theme.css`의 색상 변수(`--violet`, `--pink` 등)와 `.nav-link`/`.action-pill`/`.page-hero`/`.sync-badge`는 공통으로 쓴다.
- **모달 껍데기(리본 장식 모달)**: `random.html`의 목록 모달과 `random-admin.html`의 수정/이름변경 모달이 시각적으로 동일한 리본 모달 스타일(`.modal-overlay`/`.modal-ribbon`/`.modal-exit`)을 쓰지만, **이 CSS는 두 파일에 완전히 각각 따로 정의**돼 있고 공용 자산으로 뽑혀 있지 않다 — 재설계 시 한쪽만 고치면 다른 쪽과 어긋날 수 있는 지점.
- **실시간 동기화 방식**: 두 페이지 다 소켓이 아니라 **7초 폴링**으로 "실시간 연결됨" 배지를 유지한다. 두 사람이 동시에 관리자 페이지를 열고 있으면 최대 7초의 반영 지연이 생길 수 있다.
- **역할/관계성 데이터의 소유권**: 데이터를 **만들고 고치는 곳은 `random-admin.html`뿐**이고, `random.html`은 그 결과를 읽어서 뽑기에 쓰기만 한다 — 재설계 논의에서 "관리자 페이지 없이 뽑기 페이지에서 바로 태그를 고치게 할까?" 같은 통합 제안이 나올 수 있는데, 지금은 완전히 분리돼 있다는 걸 전제로 삼아야 한다.
